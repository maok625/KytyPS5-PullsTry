# Hadron KosmicKrisp patch audit for Kyty

This is a review queue, not an instruction to copy patches directly. Hadron pins Mesa at
`30da39187d8d3cf03c58ecd2bebb497b84501f51`; Kyty must be compared against the exact Mesa/
KosmicKrisp revision in the active branch before any patch is ported.

## Candidate queue

| Hadron patch | Subject | Why it matters to Kyty | Required validation |
|---|---|---|---|
| 0039 | Scalarise clip/cull distance loads | Relevant to shader stages that consume clip/cull distances; matches a known area of our shader-recompiler work | Vertex/tessellation/geometry/fragment stage tests, array and scalar IO, Vulkan clip/cull CTS |
| 0079 | Lock 64-bit atomics without lane turns; longer wait | Relevant to M4 devices where native 64-bit shared/workgroup atomics may be unavailable and KosmicKrisp lowers them | contention/stress tests, progress/deadlock tests, compare returned old values for all atomic ops, Vulkan memory-model CTS |
| 0085 | Emulate depth bounds below Apple family 10 | M4's Apple GPU family is below family 10 in the device data we have; feature currently needs a correct fallback if requested | dynamic/static bounds, depth writes, stencil, sample masks, early fragment tests, multisampling, performance test and depth-bounds CTS |

## Important cautions

### 0039 — clip/cull distances

The patch expands scalarisation to shader inputs as well as outputs for non-vertex stages and
checks I/O semantics instead of only store-output instructions. Verify that the target Mesa
revision has the same NIR helper and lowering sequence. Do not treat a successful compile as a
correctness test: include shaders that load a whole clip/cull array and shaders that load
individual components.

### 0079 — 64-bit atomics

Hadron's patch header identifies this change as generated by an LLM. The visible diff removes a
lane-turn locking path and changes the fallback lock-state handling and spin limit. That is a
useful lead, not sufficient evidence to port it blindly.

Before porting, verify mutual exclusion, forward progress under contention, memory ordering,
return values for exchange/compare-exchange/add/min/max/bitwise operations and behaviour when a
workgroup is partially active. Add stress tests that can detect a lock stuck forever. Keep
feature reporting honest if some atomic scopes or operations are not implemented.

### 0085 — depth bounds

This is a substantial driver implementation, not a small feature flag. It ends/restarts render
passes to make attachment depth available to a fragment-shader variant and has limitations
documented by Hadron (notably some early-fragment-test shaders that also write memory, and
overlapping depth-writing draws). Port only after reviewing the whole implementation and its
tests. Measure render-pass breaks and shader-variant compilation cost on M4.

## Cross-check against Kyty's current failures

Before making changes, collect:
- current KosmicKrisp/Mesa commit and local patch set;
- enabled Vulkan features/extensions and reported properties on the M4;
- shader compiler logs for the title/test that demonstrates each problem;
- current test result and a minimal reproducer.

Record a per-patch disposition: `port`, `adapt`, `already-fixed-upstream`,
`not-applicable` or `defer`. Keep each change separate so regressions can be bisected.
